## 三、关键点（设计决策与核心实现）

### 3.1 交易可靠性三件套（防超卖/防重/超时）
- **防超卖**：原子扣库存 `UPDATE ec_sku SET stock=stock-n WHERE stock>=n`，不加乐观锁插件，一条 SQL 解决并发
- **防重复下单**：`(user_id, idempotency_key)` 唯一索引 + 重复提交兜底返回原订单
- **防死单**：15 分钟超时任务扫描未支付订单 → 取消并释放库存/退回优惠券；支付回调条件流转（幂等）

### 3.2 状态机集中校验
订单所有流转（支付/发货/收货/取消/退款）收口在一张 `LEGAL_TRANSITIONS` 合法迁移表（0→{1,4}；1→{2,5}；2→{3}；5→{6,1}），非法流转统一抛错——前后台行为一致，杜绝越权状态。

### 3.3 智能客服的四层分流（历次演进后的最终形态）
```
①知识库规则命中（2-gram 余弦+包含度，阈值 0.85 可配）→ 0.02s 秒回
②订单查询层（按登录用户匹配真实订单：列表/第N单/最早最晚/单号直查）→ 0.03s，数据 100% 真实
③DeepSeek R1 兜底（提示词 = 角色约束 + 知识库 + 在售商品目录；答不了如实说）
④转人工 + 待补充问题闭环（客服主管补库后自动移出，补充后再问即命中）
```
`ec_sys_config.chat_llm_enabled` 一键切规则版/大模型版；`ec_chat_log.source` 记录每条回答来源（rule/order/llm/transfer）。

### 3.4 "让大模型闭嘴"的数据类问答原则
订单、金额、时间这类**事实性数据绝不让模型转述**：要么后端直出固定格式（订单查询），要么给模型时强约束"数字不可改"。实践验证：R1 在无数据时会"假装转人工"、会答"无法读取您的订单"——**意图要拦住，数据要喂准**。

### 3.5 轻量 RAG + 目录注入
知识库全量（23 条）与在售商品摘要（50 条带价格）直接进提示词——6-50 条规模无需向量检索，效果实测："iPhone 17 多少钱"报真实价格、"2000 以内买什么"如实说没有。

### 3.6 规则参数全部走配置表
置信度阈值/预警阈值/预测权重/退款是否回滚库存/大模型开关都在 `ec_sys_config`——运营可调，答辩可演。

### 3.7 知识库 = "模型的记忆"
沉淀闭环：会话记录里 R1 答过的问题 → 浓缩成标准问法+相似问法入库 → 下次秒回（对比方法：实发一句看 source 是 llm 还是 rule）。

### 3.8 演示数据工程化
`data_generator.py` 生成可重复执行的 `data.sql`（先清后插，id 固定）；`upload_images.py` 生成渐变配图走真实 `/file/upload` 上传 MinIO——演示数据同时验证了上传链路。

## 四、雷点清单（踩过的坑 → 解法）

### 4.1 环境雷
| 坑 | 症状 | 解法 |
|---|---|---|
| 本机默认 JDK 17/21 | Lombok 编译报 `JCImport ... qualid` | 构建/IDEA/Runner 全部显式 JDK 1.8 |
| 终端是 GBK | curl 发中文 JSON 解析失败；python 打印中文/¥ 直接崩 | 带中文的请求/脚本写 UTF-8 文件执行；输出重定向到文件 |
| jar 文件被运行进程锁住 | `mvn clean` 报 Failed to delete jar | 构建前先 `taskkill` 占用 8888 的进程 |
| 文档说 MySQL 8，实际 5.7.28 | 语法兼容风险 | 全部 DDL/查询按 5.7 写 |
| MinIO 重启机器后不在 | 商品图全裂 | 记进 README/遗留提醒，手动启动 |

### 4.2 MyBatis-Plus 雷（最扎堆）
| 坑 | 症状 | 解法 |
|---|---|---|
| 逻辑删除按**实体属性名**生效 | 购物车"删除后重加"撞唯一键（`uk_user_sku`） | 需物理删除的实体（Cart/UserRole/RoleMenu）**不映射 delFlag 属性** |
| `selectCount` 返回类型 | Long/Integer 编译错 | 本项目版本用 `Integer` 接 |
| `update()` 返回 boolean | 拿不到影响行数 | 用 `getBaseMapper().update(null, wrapper)` |
| `.last("ORDER BY 别名")` | `Unknown column 'lastTime'` | SQL 里用原列别名（`last_time`），`DATE_FORMAT(...) AS last_time` 直接回字符串 |
| 自定义分页查询 | 注解 SQL + IPage 参数 | 首参 `IPage<Vo>`，插件才能分页 |

### 4.3 数据与脚本雷
| 坑 | 症状 | 解法 |
|---|---|---|
| **id 段分配前没查已删数据** | 旧测试类目（del_flag=1，id 4-9）占位 → `INSERT IGNORE` 静默跳过 → 商品挂到已删类目，看板出现"未分类" | 分配 id 前查**全量含 del_flag=1**；演示类目改用 401+ 安全段；data.sql 清理段物理删除 4-11 |
| `json.dumps` 生成的 SQL 逗号后**带空格** | 补丁脚本对 ecom.sql 匹配失败 | 手写行与生成行格式分开处理，匹配串抄文件原文 |
| 中文文件名 | Edit 工具间歇报 "File has not been read yet" | 一律用 python 脚本做文本替换 |
| 演示数据合理性 | 退款单被种了"发货时间"（状态机里退款只从待发货来） | 生成器按状态机时间线生成（退款单无发货/物流） |

### 4.4 前后端交互雷
| 坑 | 症状 | 解法 |
|---|---|---|
| vue-router 同路由仅 query 变化 | 组件复用不重载——客服里连点多个订单链接，永远停在第一单 | `watch(() => route.query.orderNo)` 重新加载 |
| ResizeObserver 告警 | Element Plus 表格测量告警被 webpack 浮层放大成**全屏报错** | `devServer.client.overlay.runtimeErrors` 过滤已知无害告警 |
| dev server 首编译阻塞 + axios 10s 超时 | 改完代码立刻刷新测试，请求超时 → 客服显示"服务暂时不可用" | 等编译完成再测；客服请求单独放宽 60s |
| 聊天里的订单号不可点 | 用户要求直达详情 | 正则识别 EC 单号渲染为链接（`parseSegs`），跳 `/order/detail` |
| 多行回复挤成一行 | `\n` 在 div 中被折叠 | 气泡加 `white-space: pre-wrap` |

### 4.5 安全与工程雷
| 坑 | 症状 | 解法 |
|---|---|---|
| JWT 密钥硬编码在代码 | 工程检查不过 | 挪 `application.yml` 的 `jwt.key`（JwtKeyConfig 注入）；**提交仓库版本密钥留空，本地填真实值** |
| **单 token 会话设计** | 同账号二次登录（另一浏览器/脚本）→ 旧 token 立即 401（百问压测第 45 题全体中断的根因） | 复现确认机制；作为已知取舍记录（单端无感，多端互踢），改进方向=多 token 并存 |
| 调试残留 | 开发期 SQL 控制台打印、测试账号/测试类目 | P8 统一清理：去 StdOutImpl、data.sql 物理清理、补 @OperLog |
| 演示数据被改乱 | 答辩演示前状态不可控 | `data.sql` 先清后插可重复执行，一条命令复位 |

### 4.6 智能功能特有雷（做规则/大模型时才会遇到）
| 坑 | 症状 | 解法 |
|---|---|---|
| 中文数字映射差一位 | "第十单"被当成第 11 笔（字符表 index+1，"十"=第 10 个位置） | 写正经中文数字解析（十=10、十一=11、二十一=21） |
| 关键词式意图的漏判 | "查询一下我账户下的订单"漏给大模型 → R1 答"无法读取您的订单"（显得很蠢） | 升级为 **关键词 + 组合规则（我/查/看+订单/下单/购买）+ 排除表** |
| 政策问题误路由 | "快递能放驿站吗"被当物流查询 → 回了订单列表 | 订单层加政策排除表（能放/放驿站/指定快递…） |
| "最早"未识别 | 最早一单/最晚一单返回同一单（都掉进正则"一单"→1） | 最早→id 升序第一条；最晚→最新；互斥单独判断 |
| 关键词误伤 | "退款要**人工**审核吗"被当转人工请求 | 撤掉宽泛词"要人工"，转人工识别改用"强词 + 短句长度启发式（≤6 字）" |
| R1 假装转接 | 用户发"转人工"，R1 回复"正在为您转接"但系统没登记 | 转人工请求在意图层拦截 → 真实落库分流 |
| R1 会改数字/编政策 | 订单数据交给模型润色有篡改风险；未知政策会编 | 数据类直出不经模型；政策类提示词强约束"不编造、建议转人工" |
| 相似问法不覆盖口语变体 | "我要退款/邮费咋算/券在哪领"都漏到 R1 | 按压测结果批量补相似问法（27 个）+ 会话问题沉淀闭环 |

## 六、一句话经验（如果重做一遍）

1. **环境真相先行**：JDK/MySQL 版本、终端编码、构建命令，第一天就固化进 CLAUDE.md，省掉一半返工
2. **id 段与演示数据从"全量含已删"出发**：脚本要可重复执行，"先清后插 + 固定 id"是演示系统的命脉
3. **数据的事别交给模型**：规则兜数据、模型兜语言；意图识别用"组合规则+排除表"，单靠关键词必漏
4. **每个"智能"功能都要有兜底层**：R1 挂了转人工、规则没命中走 R1、网络炸了回退结构化文本——可降级才敢上生产
5. **坑要当场记**：本文档 4.1-4.6 的每条坑都是现场记录，不依赖回忆
