## 二、完整实现 vs 简化实现（答辩说明用）

### 完整实现（端到端闭环，含边界与异常处理）

| 模块 | 说明 |
|---|---|
| 认证与 RBAC | JWT + Redis 登录态（24h）；用户/角色/菜单/按钮四级权限；super_admin 直通；动态路由菜单；消费者自助注册 |
| 类目与商品 | 类目树不限层级；商品-SKU 规格笛卡尔积对账保存；上下架（库存全 0 自动下架）；MinIO 图片上传 |
| 交易闭环 | 下单即原子扣库存（防超卖：`UPDATE ... WHERE stock>=n`）；幂等键+唯一索引防重复下单；15 分钟超时自动取消并释放库存/退券；支付回调条件流转幂等 |
| 售后 | 订单状态机集中校验（非法流转拒绝）；退款申请→审核（通过回滚库存按配置开关）→驳回回待发货；物流轨迹（虚拟推进） |
| 供应链智能 | 库存预警（6h 定时+手动，去重、处理标记、阈值可配）；销量预测（加权移动平均 0.5/0.3/0.2 × 周末/大促系数，新品同类目兜底，参数走配置表） |
| 数据看板 | 实时指标（GMV/支付单量/环比/转化，Redis 5min 缓存）；日/周/月趋势；热销滞销 TOP10；类目占比；转化漏斗（真实埋点+行为表）；T+1 汇总任务+手动重算；营销/商品双数据域分权 |
| 智能客服 | 规则引擎：字符级 2-gram 余弦+包含度取最大，阈值（默认 0.85）可配；达标自动回复，不达标转人工并落库；**待补充问题闭环**（转人工且未覆盖 → 客服主管补充知识库 → 自动移出，补充后再问即命中） |
| 智能搜索 | 同义词双向扩展；标题多词 OR；零结果字符集 Dice 容错（错别字）；无结果推荐相近类目商品；搜索日志→热词榜+前缀联想 |
| 工程化 | 统一响应体/错误码枚举；全局异常处理；操作日志 AOP（密码脱敏）；Swagger；演示数据生成器（可重复执行）；Nginx 部署配置；README |

### 简化实现（有意取舍，说明边界）

| 模块 | 简化到什么程度 | 为什么这样取舍 |
|---|---|---|
| 智能客服 | **规则版**：字符 2-gram 余弦+包含度，阈值可配；无机器学习、无分词/同义词库依赖 | 可解释、可运营、零额外环境依赖（不引入 NLP 框架）；未覆盖问法靠「相似问法维护+待补充闭环」兜底，职责边界清晰 |
| 人工客服 | 转人工=落库标记+进待补充列表；**无实时人工坐席 IM**（无 WebSocket 会话转接） | 课程环境不需要 IM 中间件；客服主管通过待补充问题异步处理，形成运营闭环 |
| 智能搜索 | 同义词表+字符容错（Dice）；**无拼音转换、无 Elasticsearch** | 免外部分词/检索组件；错别字场景用字符集相似度覆盖（T血→T恤 可命中） |
| 个性化推荐 | **仅行为埋点**（曝光/点击入库 `ec_user_behavior`，看板漏斗已消费）；无个性化推荐算法/推荐位 | 推荐算法超出课程范围，数据已完整采集，后续可扩展 |
| 商品评价 | 星级+文字一次性评价；**无图片评价、追评、商家回复、敏感词过滤**；仅已完成订单可评 | 覆盖「收货→评价」主链路即可 |
| 支付 | **模拟支付**：下单→模拟支付接口→模拟回调（幂等）；无真实第三方网关/签名验签 | 不引入外部支付依赖；回调幂等与状态机照真实流程实现 |
| 物流 | 发货生成运单，轨迹按发货时间**虚拟推进**（已揽收→运输中→派送中→已签收）；无快递公司接口对接 | 无真实物流账号；轨迹结构（trace_json）与真实接口返回对齐，可无缝替换 |
| 操作日志查询 | 记录完整（AOP 落 `sys_oper_log`）；**无独立查询页面**（超管可通过数据库/扩展页面查看） | 记录是重点（审计），查询页为可选 UI |
| 看板数据 | 实时指标 Redis 缓存 + T+1 离线汇总；**无实时大屏推流/OLAP 组件** | 单机课程环境，Redis+定时任务足够 |
| 消息通知 | 无短信/邮件/站内信 | 超出课程范围 |
| 发票/会员/评价体系 | 未实现 | 需求范围外 |
