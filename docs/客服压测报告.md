## 二、发现的问题与修复

### 问题 1（最影响体验）：订单意图漏判
- 现象：用户问「查询一下我账户下的订单」→ 未识别为订单查询 → 大模型答"我无法读取您账户下的订单信息"（很蠢）
- 同类漏判：`订单编号是多少` / `什么时候能到` / `我最近下单了哪些东西`
- 修复：意图识别从"纯关键词"升级为 **关键词 + 组合规则**（出现 我/查/看 ＋ 订单/下单/购买 即视为查自己订单）+ 政策类问法排除表（快递能放驿站吗/能指定快递公司吗 不再误切订单层）；订单关键词扩容 12 个

### 问题 2：「转人工」被大模型"假装"转接
- 现象：用户发「转人工」→ 大模型回复"好的，正在为您转接人工客服～"但系统**未真正登记转接**
- 修复：命中转人工关键词（转人工/人工客服/找人工/真人客服…）→ 真实分流（落库 is_transfer=1，客服主管可见）；待补充列表同步过滤此类请求，不再产生噪音

### 问题 3：知识库变体覆盖不足（大量本可秒回的问题落到大模型）
- 典型：`我要退款` / `怎么退货` / `发货要多久` / `几天能发货` / `满多少包邮` / `邮费咋算` / `券在哪里领` / `我该穿什么码` / `可以开电子发票吗` 等
- 修复：7 条已有知识补相似问法共 27 个；新增 2 条——「退款多久到账」「退换货与保修政策」（后者一次覆盖 可以换货吗/换货流程/保修多久/坏了怎么维修/七天无理由退货吗/退货运费谁承担 6 类高频问法）

### 问题 4：单 token 会话互踢（压测中断根因）
- 现象：压测进行到第 45 题时全部 401
- 根因（已复现验证）：Redis 登录态只存**最新一次登录**的 token，过滤器做全等校验——同账号在浏览器重新登录，脚本旧 token 立即失效
- 影响与口径：单端使用无感知；**同一账号多端同时登录会互踢**。属当前设计取舍（如要支持多端，可改为多 token 并存或加入续期机制）

### 问题 5（优点，保留说明）：大模型边界把关做得好
- 知识库没有的政策（货到付款/发票税点/保价/以旧换新）：**不编造**，统一如实说明并建议转人工 ✅
- 刁难与闲聊（给我免单/发个红包/帮我写作业/今天天气）：礼貌拒绝并引导回业务 ✅
- 错别字与方言自适应：`退宽`→按退款作答、`多会儿发货`、`这个能刀吗` ✅
- 会引用知识库内容作答：`发票要加税点吗` 的回答正确带出了我方开票政策 ✅
